## Фаза 0: Подготовка и проектирование (2-3 недели)
### Цель: Заложить фундамент, а не писать код.
1. Уточнение MVP (Minimum Viable Product):
- Пользователь загружает резюме (PDF/DOCX).
- Система парсит резюме и извлекает: навыки, опыт, должности, образование.
- Система анализирует 3-5 популярных job-сайтов по выбранной пользователем специальности (например, "Python-разработчик").
- Показывает разрыв (Gap Analysis): какие навыки есть, каких не хватает.
- Дает 5-7 рекомендаций курсов (например, с Coursera, Stepik) для закрытия главных gaps.
- Простой UI (веб-интерфейс).

2. Проектирование микросервисов:
- skill-parser-service: Парсинг резюме и извлечение сущностей.
- vacancy-scraper-service: Сбор и анализ вакансий.
- gap-analyzer-service: Ядро ML-логики, анализ разрыва.
- recommendation-service: Подбор курсов/материалов.
- api-gateway: Единая точка входа (FastAPI).
- user-service: Управление пользователями, аутентификация.

3. Выбор стека технологий:
- Бэкенд (каждый сервис): FastAPI (основной), Pydantic (валидация), SQLAlchemy (ORM). 
- Базы данных: PostgreSQL (основные данные), Redis (кэш, сессии), Elasticsearch (поиск по вакансиям/скиллам).
- Очереди/Сообщения: Celery + Redis (для фоновых задач, например, скрапинга) или Apache Kafka (для масштабирования).
- ML/Data Science: spaCy/NLTK (парсинг), scikit-learn (классификация навыков), sentence-transformers (векторизация, похожесть). Позже: torch/transformers.
- Инфраструктура: Docker, Docker Compose (для разработки), позже Kubernetes.
- Фронтенд: React (рекомендуется) или Vue.js. Можно начать с шаблонов FastAPI (Jinja2) для скорости.

## Фаза 1: Базовый бэкенд и первый микросервис (3-4 недели)

Настроить Docker Compose с Postgres, Redis, Elasticsearch.

2. Разработка skill-parser-service (первый и ключевой):
- Создать FastAPI приложение с эндпоинтом /parse.
- Принимать файл (PDF/DOCX) или текст.
- Парсинг файлов: Использовать pdfplumber (PDF), python-docx (DOCX).
- Извлечение сущностей (NER - Named Entity Recognition):
  - Начальный вариант: Использовать spaCy с готовой моделью en_core_web_sm + написать свои правила (Matcher) для навыков (Python, Docker, AWS).
  - Улучшение: Обучить свою NER-модель на размеченных резюме (Hugging Face Transformers) или использовать готовый API (AWS Comprehend, Google Cloud Natural Language).
- Структурированный выход:
```
{
  "skills": ["Python", "FastAPI", "Docker"],
  "experience": [{"title": "Backend Dev", "years": 3}],
  "education": [...],
  "raw_text": "..."
}
```
- Сохранять результат в PostgreSQL.

3. Разработка api-gateway:
- Создать основной FastAPI app.
- Реализовать аутентификацию (JWT токены, OAuth2 с Google/LinkedIn).
- Создать эндпоинт /api/v1/upload-resume, который:
  - Принимает файл от пользователя.
  - Вызывает (через HTTP или очередь) skill-parser-service. 
  - Возвращает task ID для отслеживания.

## Фаза 2: Сбор рыночных данных и анализ разрыва (4-5 недель)
1. Разработка vacancy-scraper-service:
- Внимание! Соблюдать robots.txt, использовать API, если есть (HH.ru, LinkedIn).
- Создать модульную систему парсеров (плагины для разных сайтов).
- Использовать aiohttp/httpx для асинхронных запросов, BeautifulSoup4/parsel для парсинга HTML.
- Извлекать из вакансий: навыки, требования, опыт, зарплату.
- Структурировать навыки: Приводить к единому словарю (например, "Python3" -> "Python", "K8s" -> "Kubernetes").
- Сохранять в Elasticsearch для быстрого поиска и агрегации.
- Запускать как периодическую задачу в Celery (раз в день/неделю).

2. Разработка gap-analyzer-service (ML-ядро):
- Векторизация навыков: Использовать sentence-transformers (модель all-MiniLM-L6-v2) для перевода навыков в числовые векторы.
- Кластеризация вакансий: Группировать похожие вакансии (K-means, DBSCAN) для выделения "профессиональных кластеров" (например, "Backend Python", "Data Engineer").
- Алгоритм Gap Analysis:
  1. Определить, к какому кластеру ближе всего пользователь. 
  2. Из кластера взять топ-20 самых частых навыков. 
  3. Сравнить со скиллами пользователя. 
  4. Рассчитать "ценность" навыка: частота в вакансиях * вес зарплаты.
- Эндпоинт /analyze-gap: Принимает ID пользователя, возвращает:
```
{
  "target_role": "Python Backend Developer",
  "existing_skills": [...],
  "missing_skills": [
    {"skill": "Kafka", "demand_score": 0.87, "salary_impact": "high"}
  ],
  "match_percentage": 65
}
```

## 🚀 СТАРТОВЫЙ КОД ДЛЯ ПАРСЕРА (пример)
```
# skill-parser-service/app/main.py
from fastapi import FastAPI, UploadFile, BackgroundTasks
from pydantic import BaseModel
from typing import List
import pdfplumber
import spacy

app = FastAPI(title="Skill Parser Service")
nlp = spacy.load("en_core_web_sm")

class ParsedResume(BaseModel):
    skills: List[str]
    experience_years: float
    education: List[str]

def extract_text_from_pdf(file_path: str) -> str:
    with pdfplumber.open(file_path) as pdf:
        return " ".join([page.extract_text() for page in pdf.pages])

def extract_skills(text: str) -> List[str]:
    doc = nlp(text)
    skills = []
    skill_keywords = {"python", "docker", "fastapi", "sql", "aws"}
    
    for token in doc:
        if token.text.lower() in skill_keywords:
            skills.append(token.text)
    
    # Дополнительно: искать навыки по паттернам
    # ...
    return list(set(skills))

@app.post("/parse", response_model=ParsedResume)
async def parse_resume(file: UploadFile):
    # Сохраняем файл временно
    contents = await file.read()
    
    # Парсим текст
    text = extract_text_from_pdf(contents) if file.filename.endswith('.pdf') else contents.decode()
    
    # Извлекаем сущности
    skills = extract_skills(text)
    
    return ParsedResume(
        skills=skills,
        experience_years=2.5,  # Заглушка
        education=[]
    )
```

## 📊 МЕТРИКИ УСПЕХА MVP
1. Точность извлечения навыков из резюме > 85%.
2. Время от загрузки до результата < 30 секунд.
3. Конверсия "посетитель -> загрузил резюме" > 20%.
4. Пользователь оценивает полезность рекомендаций > 4/5.
